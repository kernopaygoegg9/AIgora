# 08: 上下文上限與遺忘（本機估算）

**Type:** 程式（tdd）

**What to build:** 使用者為參與者設定上下文上限，並選擇是否保留問題／主題。超過上限時從最舊的整則遺忘；參與者被告知上限與用量；每個發言卡片顯示用量標籤，檢視器顯示每個參與者目前的用量。token 用本機估算（Anthropic API 是 10）。

**Scope:**
- Token 計數器介面與本機估算實作（CJK 字元每字 1 token、其他每 4 字元 1 token、無條件進位；確定性；以文字快取）。計數器由一個可替換的工廠建立，讓 10 與測試可以換掉。
- 上下文預算（spec「上下文上限與遺忘」）：片段的保留規則（系統提示、人設、用量提示、本次指示、最新共識草案一定保留；問題／主題依 `keep_question`；歷史從最舊整則遺忘）、`over_limit`、用量提示文字、`ContextUsage` 與 `forgotten_through` 的計算。
- 套用到每次呼叫：一般發言與額外呼叫；自由聊天的 `chat_summary` 不套用（`limit` 為 null，但仍記錄用量）。沒有上限時全部送出、仍記錄用量。
- 發言請求帶上這次的上下文上限，供 Adapter 使用（11 的 Ollama 用）。
- `turn_started.context`、紀錄 `turns[].context` 與 `rounds[].extra_calls[].context`。
- 前端：
  - 參與者設定視窗新增上下文上限（數字、空白 = 不限、最小 100）；表格摘要顯示上限或「不限」。
  - 右欄新增「問題／主題」保留方式（radio）與 token 計數方式顯示（讀 `/api/options` 的 `token_counter`）。
  - 發言卡片與額外呼叫的上下文標籤（「上下文 7,200 / 8,000 · 已遺忘 12 則」、沒有上限時「上下文 7,200」、`over_limit` 時紅色「已超過上限」）；討論中與唯讀紀錄一致。
  - 檢視器「上下文」區塊（有任何參與者設了上限時）：每個參與者最近一次呼叫的用量 / 上限與已遺忘則數；鎖定設定列出上下文上限與保留方式。
- 前端文字須通過 glossary 檢查（不用「記憶」「窗口」）。
