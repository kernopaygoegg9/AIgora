# 05: 主持人排定下一輪順序

**Type:** 程式（tdd）

**What to build:** 共識討論選依序時，主持人寫共識草案時在最後一行排定下一輪的發言順序；下一輪照這個順序發言。順序不合法時改用參與者清單順序並標示。畫面上在草案下方顯示「下一輪順序」。

**Scope:**
- 只在共識討論且依序時，寫草案的指示要求最後一行 `ORDER: 顯示名稱1, 顯示名稱2, ...`。
- 解析規則見 spec「主持人排定順序」（顯示名稱、不分大小寫、半形／全形逗號、剛好包含所有在場者各一次）。
- 不論合法與否，`ORDER:` 行都從草案內文移除，之後才存檔與送給其他參與者。
- 共識討論的「本輪順序」：第 1 輪清單順序；之後用上一輪草案的合法順序（刪去之後被移出的人），否則清單順序。主持人接手重寫時以最後成功的草案為準。
- `draft_created.next_order` / `next_order_source` 與紀錄對應欄位；同時發言時為 null。
- 前端：草案下方顯示「下一輪順序：A → B → C」，`default` 時加「（主持人未指定，依清單順序）」；討論中與唯讀紀錄一致。
- Fake Adapter 的 `drafts` 已可指定草案文字（含 `ORDER:` 行）；必要時在 E2E 設定檔新增會排順序的 Fake 參與者。
