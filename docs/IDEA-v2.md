# AIgora v2：專案想法（依序發言與自由聊天）

用語依 `GLOSSARY.md`；第一版的想法見 `docs/IDEA.md`，規格見 `.scratch/aigora-v1/spec.md`。

## 要解決什麼問題
第一版的參與者在同一輪裡同時發言，彼此只看得到上一輪的內容，比較像「各自交報告」，
不像真的在交談：沒辦法直接回應剛剛那個人說的話。
我也想看 AI 們在沒有任務的情況下自由聊天會聊出什麼，
以及上下文上限（它們看得到多少之前的內容）會不會改變它們聊的內容。

## 這版要做的事
1. **依序發言**：實作第一版只定了介面的「依序」發言順序，提問與共識討論都能選
2. **自由聊天**：新的討論模式，參與者固定順序輪流接話，不追求共識
3. **上下文上限**：每個參與者可以設定上下文上限，超過的舊內容直接遺忘
4. **人設**：把第一版保留的人設欄位做出來
5. **設定面板與參與者設定**：所有設定都在同一個設定面板一次設完就開始；每個參與者可以點開來各自設定（含指定主持人）

## 設定面板與參與者設定
- 一場討論的所有設定（討論模式、參與者、主持人、共識裁定方式、發言順序、輪數上限、遺忘方式等）
  都在同一個設定面板設定，一併設完就可以直接開始
- 參與者與模型都有預設值，開始前都可以調整；**開始後所有設定鎖定**（同第一版；討論中加入或移除參與者這版不做）
- **參與者設定**：在設定面板點開某個參與者，跳出它自己的設定視窗，可以設定：
  - 模型（從第一版參與者表格每一列的模型下拉選單移過來）
  - 人設（個性）
  - 上下文上限（不填 = 不限制；最小 100 tokens）
  - 設為主持人（同一場只能有一位；只在需要主持人的討論模式有意義）
- 參與者表格每一列只顯示摘要：模型、是否有人設、上下文上限、主持人標記
- 「新增參與者」（臨時參與者）保留，新增後一樣可以點開設定
- 預設值來自 `participants.toml`；在面板上改的只套用這場討論
- 主持人預設為設定檔指定的參與者（省略時為第一個）
- **提問轉共識討論**：第一版按下「開始共識討論」會直接用預設主持人、預設共識裁定方式等開始，沒有機會選。
  v2 改成按下後回到同一個設定面板：
  - 問題、參與者清單與各自的模型**鎖定**，沿用這場提問（提問的發言會直接當作第 1 輪）
  - 人設、上下文上限、主持人以及其他共識討論設定都可以改，從第 2 輪開始生效
- 自由聊天也有主持人，負責結束時寫摘要
- 主持人失敗或被移出時的接手規則沿用第一版（由清單中下一個仍在場者接手）

## 依序發言
- 同一輪內一次只有一個參與者發言，後面的人看得到同一輪前面的人剛說的話
- 一輪仍然是「每個在場參與者各說一次」
- 各討論模式的順序：
  - **提問**：依參與者清單順序
  - **共識討論**：第 1 輪依參與者清單順序；之後由主持人在寫共識草案時一併排定下一輪的順序（不增加額外呼叫）。
    排順序的那一行從草案內文拿掉（不讓其他人當作草案內容表態），畫面上在草案下方另外顯示「下一輪順序：Codex → Claude → Ollama」；
    不合法而退回清單順序時標示「（主持人未指定，依清單順序）」
  - **自由聊天**：固定依參與者清單順序輪流（A→B→C→A…）
- 取代第一版「每輪輪換第一位發言者」的依序規則
- 插話：正在說的不打斷，從**下一個發言**開始生效（同時發言時維持第一版的「下一輪」）
- 依序發言時串流仍照常顯示，只是一次只有一個人在說
- **畫面**：依序發言時，同一輪的發言依發言順序由上往下排列；同時發言維持左右並排。唯讀紀錄相同

## 自由聊天（新討論模式）
- 主題可給可不給；沒給時由第一位發言者自己開話題
- 參與者固定順序輪流接話，不表態、不需要共識草案、不判斷共識
- 指示要求像聊天一樣自然、簡短（約 1–3 段），直接回應前面的人；不設硬性字數上限
- 只依輪數上限結束（或我手動停止）；預設輪數上限 100（`participants.toml` 的 `[defaults] chat_max_rounds`，切到自由聊天時設定面板自動帶入）
- 結束時由主持人寫一份聊天摘要（多一次呼叫），摘要時看完整紀錄，不受主持人自己的上下文上限限制
- 中途結束：
  - 我按停止：不寫摘要，立即結束（同第一版的停止）
  - 參與者不足 2 個而結束：仍在場的主持人寫摘要；主持人也不在了就不寫
- **畫面**：結果區塊顯示主持人的摘要，沒有摘要時顯示結束原因；檢視器不顯示表態追蹤；歷史清單中沒有主題的聊天顯示「（無主題）」
- 主要用途：讓討論更像真的交談、悠閒聊天、搭配人設與上下文上限做實驗

## 上下文上限
- **目的**：觀察參與者看得到的內容多寡，會不會改變它們之間聊出的內容
- **適用**：所有討論模式；預設關閉（沒設就是第一版的行為：每次都送完整內容）
- **範圍**：每個參與者各自設定，可以讓 A 看得到很多、B 只看得到一點
- **計算什麼**：只算 AIgora 送給參與者的內容（系統提示、人設、問題／主題、之前的發言與草案、插話、本次指示），不含各 CLI 自己加的提示，也和模型本身的 context window 無關
- **單位**：token，所有參與者統一用 Claude 的算法計算（各家 CLI 的 tokenizer 不同，用同一套才能互相比較；與非 Claude 參與者實際的 token 數有誤差）
  - `.env` 有 `AIGORA_ANTHROPIC_API_KEY` 時，呼叫 Anthropic 的 token 計數 API（不收費；金鑰只有後端讀取，同 TypeSafe 金鑰）。
    不用 `ANTHROPIC_API_KEY` 這個名稱，避免和 Claude CLI 本身讀的變數混用
  - 沒有金鑰，或某次呼叫失敗時，那一次改用本機估算
  - 討論紀錄標明每次用的是哪一種
- **只管輸入**：上限只限制送給參與者的內容，不幫它的回覆預留空間，回覆長度不限
- **超過上限時**：從最舊的整則開始遺忘，不做摘要或壓縮。
  - **一定保留**：系統提示、人設、本次指示、最新一份共識草案（這一輪要對它表態）
  - **可以遺忘**：之前的發言、較舊的共識草案、插話
  - **問題／主題**：開始前選一種（所有討論模式都適用，預設保留）：
    - **保留問題／主題**
    - **問題／主題也會被遺忘**：當作一般內容，可能被忘掉
  - 一定保留的部分本身就超過上限時：仍然送出這些部分（超過上限），其他內容全部遺忘，該發言標示「已超過上限」
- **套用到哪些呼叫**：一般發言，以及主持人寫草案、最終結果、分歧整理、方式 B 的反問確認，都套用該參與者自己的上下文上限；唯一例外是自由聊天的摘要
- **參與者看得到的資訊**：只告訴它「上下文上限多少、目前用了多少」，不告訴它遺忘了什麼
- **介面**：
  - 每個發言卡片有一個標籤，例如「上下文 7,200 / 8,000 · 已遺忘 12 則」；超過上限時改成紅色「已超過上限」
  - 點標籤進入對照模式：這則發言之前、它看不到的內容（發言、草案、插話、問題／主題）全部變淡，再點一次恢復；唯讀紀錄也可以
  - 有設上下文上限時，檢視器顯示每個參與者目前的上下文用量（所有討論模式）
  - 討論紀錄也存這些數字
- **Ollama**：Ollama 預設只給模型很短的 context 並默默截斷，會污染實驗。Ollama Adapter 依這場的上下文上限（沒設時用足夠大的值）設定 `num_ctx`

## 人設
- 在 `participants.toml` 為參與者寫人設（個性、立場設定），當作預設值；最多 2,000 字，可以多行
- 開始前可以在參與者設定視窗修改這場討論的人設，開始後鎖定（跟其他設定一樣）
- 人設放進該參與者的系統提示，其他參與者看不到別人的人設原文
- 畫面上不顯示在發言卡片上；只出現在參與者設定視窗、討論中檢視器的「設定（已鎖定）」、唯讀紀錄
- 人設與「角色」（討論模式指派的職責，例如法庭的法官）仍是兩件事；角色這版不做

## 怎樣算成功
- 提問與共識討論選「依序」時，後發言的參與者會明確回應同一輪前面的人
- 自由聊天能在不給主題的情況下，讓 Claude、Codex（加選用的 Ollama）聊到輪數上限並產出摘要
- 同一個主題與人設，用不同上下文上限各跑一次，能從介面與紀錄看出每個發言當時遺忘了哪些內容
- 沒有設定上下文上限時，所有行為與第一版相同（第一版的測試全部繼續通過）
- 以上全部可以用 Fake Adapter 自動測試，不花 AI 額度

## 其他已確認的細節
- 主持人排定的下一輪順序解析不到或不合法時，退回參與者清單順序
- 主持人排順序的格式由 spec 決定（例如草案最後一行 `ORDER: id1, id2, ...`）

## 不做的事
- 吵架、法庭、爭議事件討論等其他討論模式，以及討論模式指派的角色
- 超過上下文上限時的摘要或壓縮
- 討論中加入、移除參與者或換模型（失敗自動移出除外）
- 管理 Anthropic API 計費（`AIGORA_ANTHROPIC_API_KEY` 只用於免費的 token 計數，可不提供）
- 每次發言後由主持人點名下一位（共識討論只在每輪排一次順序）
- 自由聊天以共識或 AI 自行宣告結束
- 其餘沿用第一版的「不做的事」（帳號、雲端同步、語音、圖片、桌面打包、resume 等）
