# AIgora v2：專案想法（交替對話）

用語依 `GLOSSARY.md`；第一版的想法見 `docs/IDEA.md`，規格見 `.scratch/aigora-v1/spec.md`。

## 要解決什麼問題
第一版的參與者在同一輪裡同時發言，彼此只看得到上一輪的內容，比較像「各自交報告」，
不像真的在對話：沒辦法直接回應剛剛那個人說的話。
我也想看 AI 們在沒有任務的情況下自由聊天會聊出什麼，
以及「記憶長短」（上下文窗口大小）會不會改變它們的對話。

## 這版要做的事
1. **依序發言**：實作第一版只定了介面的「依序」發言順序，提問與共識討論都能選
2. **自由聊天**：新的討論模式，參與者固定順序輪流接話，不追求共識
3. **上下文窗口上限**：每個參與者可以設定記憶上限，超過的舊內容直接丟掉
4. **人設**：把第一版保留的人設欄位做出來
5. **設定面板與參與者設定**：所有設定都在同一個設定面板一次設完就開始；每個參與者可以點開來各自設定（含指定主持人）

## 設定面板與參與者設定
- 一場討論的所有設定（討論模式、參與者、主持人、共識裁定方式、發言順序、輪數上限、窗口捨棄方式等）
  都在同一個設定面板設定，一併設完就可以直接開始，開始後鎖定（同第一版）
- **參與者設定**：在設定面板點開某個參與者，跳出它自己的設定視窗，可以設定：
  - 模型
  - 人設（個性）
  - 上下文窗口上限（不填 = 不限制）
  - 設為主持人（同一場只能有一位；只在需要主持人的討論模式有意義）
- 預設值來自 `participants.toml`；在面板上改的只套用這場討論
- 主持人預設為設定檔指定的參與者（省略時為第一個）
- **提問轉共識討論**：第一版按下「開始共識討論」會直接用預設主持人、預設共識裁定方式等開始，沒有機會選。
  v2 改成按下後回到同一個設定面板，問題與參與者沿用這場提問（不能改，因為提問的發言會當作第 1 輪），
  其餘設定照常調整後再開始
- 自由聊天也有主持人，負責結束時寫摘要
- 主持人失敗或被移出時的接手規則沿用第一版（由清單中下一個仍在場者接手）

## 依序發言
- 同一輪內一次只有一個參與者發言，後面的人看得到同一輪前面的人剛說的話
- 一輪仍然是「每個在場參與者各說一次」
- 各討論模式的順序：
  - **提問**：依參與者清單順序
  - **共識討論**：第 1 輪依參與者清單順序；之後由主持人在寫共識草案時一併排定下一輪的順序（不增加額外呼叫）
  - **自由聊天**：固定依參與者清單順序輪流（A→B→C→A…）
- 取代第一版「每輪輪換第一位發言者」的依序規則
- 插話：正在說的不打斷，從**下一個發言**開始生效（同時發言時維持第一版的「下一輪」）
- 依序發言時串流仍照常顯示，只是一次只有一個人在說

## 自由聊天（新討論模式）
- 主題可給可不給；沒給時由第一位發言者自己開話題
- 參與者固定順序輪流接話，不表態、不需要共識草案、不判斷共識
- 只依輪數上限結束（或我手動停止）
- 結束時請一位參與者寫一份聊天摘要（多一次呼叫）
- 主要用途：讓討論更像真的對話、悠閒聊天、搭配人設與窗口上限做實驗

## 上下文窗口上限
- **目的**：觀察不同記憶長短下，參與者之間的對話內容會不會改變
- **適用**：所有討論模式；預設關閉（沒設就是第一版的行為：每次都送完整內容）
- **範圍**：每個參與者各自設定，可以讓 A 記得很多、B 只記得一點
- **單位**：token，所有參與者統一用 Claude 的算法計算（各家 CLI 的 tokenizer 不同，用同一套才能互相比較；與非 Claude 參與者實際的 token 數有誤差）
  - `.env` 有 `ANTHROPIC_API_KEY` 時，呼叫 Anthropic 的 token 計數 API（不收費；金鑰只有後端讀取，同 TypeSafe 金鑰）
  - 沒有金鑰時，改用本機估算
  - 討論紀錄標明這場用的是哪一種
- **只管輸入**：上限只限制送給參與者的內容（它能記得多少），不幫它的回覆預留空間，回覆長度不限
- **超過上限時**：直接捨棄，不做摘要或壓縮。捨棄方式有兩種，開始前選一種：
  - **保留主題**：系統提示、人設、主題永遠保留，其餘從最舊的發言整則移除，直到放得下
  - **主題也會被忘**：只有系統提示與人設保留，主題也當作一般內容，可能被忘掉
- **參與者看得到的資訊**：只告訴它「記憶上限多少、目前用了多少」，不告訴它忘掉了什麼
- **介面**：每個發言標示該參與者當時的窗口用量，以及它看不到（已遺忘）的範圍，方便對照「它說這句話時忘了什麼」；討論紀錄也存這些數字

## 人設
- 在 `participants.toml` 為參與者寫人設（個性、立場設定），當作預設值
- 開始前可以在參與者設定視窗修改這場討論的人設，開始後鎖定（跟其他設定一樣）
- 人設放進該參與者的系統提示，其他參與者看不到別人的人設原文
- 人設與「角色」（討論模式指派的職責，例如法庭的法官）仍是兩件事；角色這版不做

## 怎樣算成功
- 提問與共識討論選「依序」時，後發言的參與者會明確回應同一輪前面的人
- 自由聊天能在不給主題的情況下，讓 Claude、Codex（加選用的 Ollama）聊到輪數上限並產出摘要
- 同一個主題與人設，用不同窗口上限各跑一次，能從介面與紀錄看出每個發言當時忘了哪些內容
- 窗口上限關閉時，所有行為與第一版相同（第一版的測試全部繼續通過）
- 以上全部可以用 Fake Adapter 自動測試，不花 AI 額度

## 已確認的細節
- 自由聊天的摘要撰寫時看完整紀錄，不受主持人自己的窗口上限限制
- 主持人排定的下一輪順序解析不到或不合法時，退回參與者清單順序
- 主持人排順序的格式由 spec 決定（例如草案最後一行 `ORDER: id1, id2, ...`）
- 自由聊天預設輪數上限 100

## 不做的事
- 吵架、法庭、爭議事件討論等其他討論模式，以及討論模式指派的角色
- 窗口超過時的摘要或壓縮
- 管理 Anthropic API 計費（`ANTHROPIC_API_KEY` 只用於免費的 token 計數，可不提供）
- 每次發言後由主持人點名下一位（共識討論只在每輪排一次順序）
- 自由聊天以共識或 AI 自行宣告結束
- 其餘沿用第一版的「不做的事」（帳號、雲端同步、語音、圖片、桌面打包、resume 等）
