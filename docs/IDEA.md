# AIgora：專案想法

## 要解決什麼問題
我同時在用 Codex CLI、Claude Code、Gemini CLI，同一個問題常常要開三個終端機分別問，
再自己來回複製貼上比較答案，很麻煩。

## 給誰用
- 主要給自己用
- 其他想用的人（本專案開源）

## 核心功能
- 我開一個話題或問一個問題，在一個視窗裡同時看到多個 AI 的回覆
- 輸入一次，可以選擇發給全部或其中幾個 AI
- AI 可以隨時加入或移除（用設定檔或介面），新增一個 AI 不需要改核心程式
- 討論模式：AI 互相看到對方的回答，接力討論直到取得共識（規則見下節）

## 共識討論的規則（草稿）
- **輪次**：每一輪，每個參與的 AI 都會看到題目與之前所有 AI 的發言，再發表一次意見
- **共識判斷方式**：有兩種，開始討論前選一種（之後可能再加，所以要能替換）
  - **A. 主持人 + 全員表態**
    - 表態：每次發言最後要明確表態「同意目前的共識草案」或「不同意」，並附上理由
    - 共識草案：由一個 AI 擔任主持人（可在設定中指定，預設為第一個 AI），
      每輪結束後根據大家的發言整理出一份共識草案
    - 達成共識：所有參與的 AI 都表態「同意」同一份共識草案
  - **B. Jev 判斷 + 反問確認**（實驗性，先看效果）
    - 每輪結束後，把本輪所有發言交給 Jev（TypeSafe 的模型），判斷「是否已取得共識」
    - Jev 判斷為否：進入下一輪
    - Jev 判斷為是：反問每個 AI「你是否認為已取得共識？」
      - 全部回答是：結束討論，輸出共識結果
      - 有任何一個回答否：把它的理由加入討論，進入下一輪
    - 需要 TypeSafe API 金鑰（見「不做的事」中的例外）
- **輪數上限**：預設最多 15 輪（可設定），避免停不下來和消耗過多額度
- **未達成共識**：到達上限時停止，輸出「各 AI 的最終立場」與「仍有分歧的重點」
- **使用者介入**：討論中我可以隨時插話（補充資訊或改問題）或手動停止

## 怎樣算成功
- 能同時跟 Claude Code、Codex CLI、Gemini CLI 三個 AI 對話，並在取得共識後輸出結果；
  未取得共識時，能輸出各方立場與分歧點
- 新增第四個 AI（例如 Ollama）只要加一個 adapter／設定，不用動其他程式

## 技術選型（我自己決定）
- 後端：Python
  - 負責：啟動並管理各 AI CLI 的子行程、討論流程（輪次、共識判斷）、對話紀錄存檔
  - 框架：FastAPI（HTTP + WebSocket）
  - 環境管理：uv
- 前端：TypeScript
  - 負責：顯示對話、輸入、選擇 AI、設定 AI 清單；不含任何討論邏輯
  - 框架：（待決定，例如 React + Vite）
- 前後端溝通：WebSocket 即時推送每個 AI 的輸出（串流）
- 介面順序：先做網頁版（快速測試），之後再用 Tauri 或 Electron 包成桌面 App，
  桌面版沿用同一套前端，後端以子行程方式附帶
- AI 接入：直接操作各家 CLI 的非互動模式（子行程），每個 AI 一個 adapter
- 平台：（待決定，例如第一版先支援 Windows）

## 未來方向（第一版不做，只寫在這裡讓設計預留空間）
- 討論「模式」可擴充：吵架、法庭（有法官與控辯雙方）、爭議事件討論、悠閒聊天
- 第一版只做「共識討論」這一種模式

## 不做的事
- 不做帳號系統、不做多人共用
- 不做雲端同步，對話紀錄只存在本機
- 不自己管 API 金鑰計費，沿用各 CLI 已登入的帳號
  （例外：共識判斷方式 B 使用 Jev，需要使用者自行提供 TypeSafe API 金鑰；沒有金鑰時只能用方式 A）
- 第一版不做語音、不做圖片輸入
- 第一版不做共識討論以外的模式
